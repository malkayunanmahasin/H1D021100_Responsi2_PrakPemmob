# penjelasan singkat 
Aplikasi ini terdiri dari dua bagian utama, yaitu frontend mobile menggunakan Flutter dan backend REST API menggunakan Laravel. Pada sisi mobile, aplikasi bernama “Responsi 2 Mobile Paket 3 H1D021100” menyediakan antarmuka untuk login, registrasi, serta pengelolaan inventaris buku di supermarket Malkamart. Pengguna pertama kali masuk melalui halaman login, dan jika belum memiliki akun dapat melakukan registrasi. Setelah berhasil login, pengguna diarahkan ke halaman “Inventaris Buku Malkamart” yang menampilkan daftar buku, serta dapat menambah, mengubah, dan menghapus data inventaris.

Koneksi antara Flutter dan Laravel dilakukan melalui HTTP menggunakan format data JSON. Di emulator Android, Flutter mengakses backend dengan base URL http://10.0.2.2:8000/api, yang mengarah ke server Laravel yang berjalan di http://127.0.0.1:8000 pada komputer pengembang. Flutter menggunakan sebuah kelas ApiService yang membungkus pemanggilan ke API menggunakan package http. Setiap permintaan dikirim dengan header Content-Type: application/json dan Accept: application/json, serta body yang di-jsonEncode dari model Book atau dari input login/registrasi. Respon dari Laravel yang berupa JSON kemudian di-decode dan diubah menjadi objek Dart (misalnya objek Book) untuk ditampilkan di UI.

Spesifikasi API di sisi Laravel mengikuti pola REST. Untuk autentikasi, disediakan endpoint POST /api/register yang menerima JSON berisi name, email, dan password untuk membuat akun pada tabel users. Endpoint POST /api/login menerima email dan password, kemudian memverifikasi hash password dan mengembalikan respon JSON yang berisi status keberhasilan dan data pengguna jika login berhasil. Pada tahap ini aplikasi belum menggunakan token kompleks (JWT/Sanctum), sehingga login lebih difokuskan pada validasi kredensial dan penyimpanan data user dasar di SharedPreferences pada sisi Flutter.

Untuk fitur inventaris buku, Laravel menyediakan endpoint GET /api/books untuk mengambil semua data buku, POST /api/books untuk menambah data baru, GET /api/books/{id} untuk melihat detail satu buku, PUT /api/books/{id} untuk mengubah data buku, dan DELETE /api/books/{id} untuk menghapus buku. Field yang digunakan konsisten dengan kebutuhan sistem: judul (string), harga (int), jumlah (int), tanggal_masuk (string), volume (int), penulis (string), dan penerbit (string). Flutter membangun objek Book dari input form, lalu mengirimkannya ke endpoint yang sesuai (POST untuk tambah, PUT untuk edit), dan setelah operasi berhasil daftar buku akan di-refresh dengan memanggil kembali GET /api/books. Dengan alur ini, integrasi antara Flutter dan Laravel berjalan end-to-end: mulai dari autentikasi pengguna hingga pengelolaan penuh data inventaris buku di database.

Pada sisi Laravel, di AuthController, fungsi register() bertugas menerima data pendaftaran berupa name, email, dan password dari request. Fungsi ini terlebih dahulu memvalidasi input (misalnya email unik, password minimal panjang tertentu), lalu membuat record baru di tabel users dengan password yang sudah di-hash menggunakan Hash::make(). Jika berhasil, fungsi ini mengembalikan respons JSON dengan status sukses dan data user yang baru dibuat. Fungsi login() menerima email dan password, melakukan validasi format, kemudian mencari user berdasarkan email. Jika user ditemukan, Hash::check() digunakan untuk membandingkan password input dengan hash di database. Bila cocok, fungsi mengembalikan JSON sukses berisi data user; jika tidak, fungsi mengembalikan status gagal (401) dengan pesan bahwa email atau password salah. 

Di BookController, fungsi index() mengambil semua record buku dari tabel books menggunakan Book::all() dan mengembalikannya sebagai JSON, yang digunakan Flutter untuk mengisi daftar inventaris. Fungsi store() menerima data buku baru (judul, harga, jumlah, tanggal_masuk, volume, penulis, penerbit), memvalidasi tipe dan kelengkapan data, lalu membuat record baru dengan Book::create(). Fungsi show($id) mencari satu buku berdasarkan id, jika ditemukan dikembalikan sebagai JSON, jika tidak mengembalikan status 404. Fungsi update(Request $request, $id) logic-nya mirip store(): cari data buku berdasarkan id, validasi data baru dari request, lalu panggil $book->update($data) dan mengembalikan JSON sukses. Terakhir, fungsi destroy($id) mencari buku lalu menghapusnya dengan $book->delete(). Bila id tidak ditemukan, fungsi show/update/destroy sama-sama mengembalikan JSON error 404 agar frontend tahu bahwa data sudah tidak ada. 

Pada sisi Flutter, kelas ApiService adalah jembatan utama ke backend. Fungsi register(name, email, password) membentuk request POST ke endpoint /register, mengirim body JSON berisi tiga field tersebut, dan mengembalikan true jika status kode HTTP adalah 201 (berhasil dibuat). Fungsi login(email, password) mengirim POST ke /login dengan JSON yang berisi email dan password; jika respons 200 dan success == true, fungsi ini menyimpan user_id dan user_name ke SharedPreferences untuk menandai bahwa user sedang login, lalu mengembalikan true. Fungsi logout() hanya membersihkan semua data di SharedPreferences. Untuk inventaris, getBooks() memanggil GET /books, membaca body JSON berupa array buku, kemudian memetakan tiap elemen menjadi objek Book. Fungsi createBook(book) dan updateBook(book) masing-masing mengirim POST /books dan PUT /books/{id} dengan body jsonEncode(book.toJson()); keduanya mengembalikan true jika status kode masing-masing 201 atau 200. Fungsi deleteBook(id) memanggil DELETE /books/{id} dan mengembalikan true jika status kode 200. 

Di layer UI Flutter, pada LoginPage, fungsi _doLogin() bertugas mengambil input email dan password dari form, memvalidasi bahwa keduanya tidak kosong, lalu memanggil ApiService.login(). Sebelum memanggil API, fungsi ini mengaktifkan indikator loading dengan mengubah _loading = true. Setelah menerima hasil, jika login berhasil, halaman berpindah ke BookListPage menggunakan Navigator.pushReplacement, dan jika gagal, menampilkan SnackBar berisi pesan error. Fungsi _doRegister() di RegisterPage bekerja mirip: memvalidasi input nama, email, password, memanggil ApiService.register(), dan jika sukses menampilkan pesan “Registrasi berhasil” kemudian kembali ke halaman login dengan Navigator.pop(). 

Di BookListPage, initState() menginisialisasi _futureBooks dengan memanggil ApiService.getBooks() untuk mengisi daftar buku pertama kali. Fungsi _refresh() digunakan untuk me-refresh data setelah operasi tambah/edit/hapus dengan meng-set ulang _futureBooks ke pemanggilan getBooks() baru agar FutureBuilder menggambar ulang daftar. Fungsi _logout() memanggil ApiService.logout() untuk menghapus data login yang tersimpan, lalu menavigasi pengguna kembali ke halaman login dengan Navigator.pushAndRemoveUntil. Fungsi _getUserName() membaca user_name dari SharedPreferences untuk ditampilkan di AppBar sebagai informasi akun aktif. Fungsi _confirmDelete(book) menampilkan dialog konfirmasi, lalu jika user memilih “Hapus”, memanggil ApiService.deleteBook(book.id!) dan menampilkan SnackBar sesuai hasil, serta memanggil _refresh() bila berhasil. 

Terakhir, pada BookFormPage, fungsi initState() mengatur mode halaman apakah “tambah” atau “edit”. Jika menerima objek Book lewat parameter, field form diisi dengan nilai buku tersebut untuk diedit; jika tidak, otomatis mengisi tanggal masuk dengan tanggal hari ini. Fungsi _pickDate() membuka showDatePicker, dan jika user memilih tanggal, nilai tersebut diformat (yyyy-MM-dd) dan dimasukkan ke TextEditingController tanggal. Fungsi _save() adalah inti proses simpan: memvalidasi semua field form, mengonversi input numeric ke int, membentuk objek Book baru (dengan id terisi jika sedang edit), lalu memanggil ApiService.createBook() atau ApiService.updateBook() sesuai mode. Fungsi ini juga mengatur flag _loading agar tombol tidak bisa ditekan berulang, menampilkan SnackBar jika sukses atau gagal, dan jika berhasil memanggil Navigator.pop(context, true) untuk memberi sinyal ke halaman sebelumnya agar me-refresh daftar buku. Dengan kombinasi fungsi-fungsi ini, alur login–lihat data–tambah/edit/hapus inventaris dapat berjalan secara utuh dari Flutter ke Laravel dan kembali lagi ke antarmuka pengguna.
